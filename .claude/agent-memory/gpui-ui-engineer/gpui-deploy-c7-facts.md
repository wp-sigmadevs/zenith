- `IconButton::tab_index(impl Into<isize>)` needs `0isize` (a bare `0` is i32 and fails); `DropdownMenu::tab_index(isize)` and `FocusHandle::tab_index(isize)` take a plain literal. `ButtonLike` sets `tab_stop(!disabled)`, so a disabled icon button is skipped by Tab.
- `DropdownMenu::new_with_element(..)` sets no default `aria_value` (only the text label does): pass `.aria_value(name)`. `.handle(PopoverMenuHandle<ContextMenu>)` is `ui::PopoverMenuHandle` (ui/src/components/popover_menu.rs:62 `show(window, cx)`, `is_deployed()`); a wrapper div's `menu::Confirm` handler can `handle.clone().show(window, cx)` (on_open updates the menu entity, not the panel: no lease clash).
- Enter on a focused icon button reaches the panel's `menu::Confirm` (opens the selected row) unless an ancestor div handles `menu::Confirm`: the `pressed` wrapper (copy of dialog.rs) fixes it. `zenith_deploy::FocusNextControl/PreviousControl` are the dialog's actions, reused (`dialog::{FocusNextControl, FocusPreviousControl}`); panel handles them with plain `window.focus_next/prev` (no wrap). Panel handle: `cx.focus_handle().tab_index(0).tab_stop(true)`. In tests, load `default-macos.json` + `zenith.json` through `settings::KeymapFile::load` + `cx.bind_keys` (copy of dialog tests `load_keymaps`), then `simulate_keystrokes("tab tab enter")`: panel -> dropdown -> "..." -> Collapse.
- `ListItem` content is `flex_shrink_0`: a long label never wraps or shrinks, it overflows the panel. For lines that carry server text use `h_flex().pl(..).pr_2()` + `div().min_w_0()` (the existing `a_long_error_or_upload_line_stays_inside_the_panel` test catches it).
- Listings run through ONE session mutex, in spawn order, even though `list()` calls are concurrent; the gate of a `FakeRemote.list_gates` entry holds that mutex, so a later folder cannot finish before an earlier gated one. A test where a folder fails LAST must gate and refuse the LAST folder of the chain. `operations.insert("list:{path}")` replaces (cancels) an earlier in-flight list of the same path, so a double root listing is invisible in `FakeRemote.log()`: the "select_opened before focus_panel" order cannot be proven by a test. A successful `list` clears `status`: a failure that must stay visible needs `say()` (notice + toast).
- Test pitfall: dispatching an action that ends in `workspace.focus_panel` opens the panel and lists the root (`set_active`); show the panel first (`focus_panel` + park) before counting `FakeRemote.log()` lines for "nothing listed".
- A heredoc containing `git commit -m` text next to the commit hook trips "not conventional"; write scripts with the Write tool, commit in its own call. `git stash` + `pop` is fine for a baseline `cargo fmt --check` count, but prefer a plain `git diff` check.
- Sabotage runner kept in scratchpad `sab.py` (list of (name, [(file, old, new)], nextest filter); restores in `finally`; backup copies in `scratchpad/backup/`).

### Known gaps (from reviews; fix next)
- **HTTP history, fix first**: `strip_url_userinfo` (`history.rs` ~249) only handles the literal `://` form, but `Url::parse` also accepts `https:/user:pw@host`, `https:user:pw@host`, three or more slashes and backslashes, so those URLs send and the userinfo is stored in the entry file and `index.json` (local data dir only). Fix: when `Url::parse` succeeds clear username/password on the parsed URL and store `url.as_str()`; for template URLs that fail to parse skip any run of `/` and `\` after the first colon; end the authority at a backslash. Add tests for each shape on both files. Before this session those URLs were stored fully raw, so this is not a regression.
- **Deploy**: unwritten tests (save with a damaged `servers.json`; switching servers keeps each server's fields); untested: a failing Keychain write, `store.save` failing after the writes, the order of the session-password changes (test: set a session password for the old target, abort the save, assert it survives); message "Nothing was saved" is not always true (deletes can partly succeed); ticking Anonymous deletes a saved password with no note; Esc during a save can lose the disk write; cached remote copies are never cleaned except on server removal/disconnect; macOS Keychain behaviour not run for real (only a fake).

- **PHP**: `find_php` retry only on the status path; the Status click runs two `php -v` lookups; a failed newest own-config write has no timed retry; the dialog's superseded-write restart rule is covered by tests that use the fake filesystem only.
- **Scratches**: an open scratch tab loses its worktree on share (no LSP until reopened); a scratch opened from the panel while shared goes to guests as an invisible single-file worktree.
